# دليل SEO وGEO

الموقع عربي ويعرض هوية عبدالسلام معاد، وخدماته، وخبراته، ودراسات مشاريعه. هدف التحسينات جعل هذا المحتوى متاحًا للفهرسة والفهم والاقتباس، مع الحفاظ على تجربة الملف التفاعلي. لا تضمن هذه التغييرات ترتيبًا محددًا أو ظهورًا في إجابات الذكاء الاصطناعي.

## ما يتطلبه النشر

النطاق الأساسي المؤكد هو [abdulsalam.pro](https://abdulsalam.pro/)، والقيمة الافتراضية في إعدادات البناء هي `VITE_SITE_URL=https://abdulsalam.pro/`. إذا نُقل الموقع لاحقًا، اضبط المتغير في بيئة البناء على رابط الموقع الأساسي الكامل، مع مسار النشر إن وجد.

هذا المتغير يحدد الروابط الأساسية `canonical` وعناوين البيانات المنظّمة وصورة المشاركة وخريطة الموقع. إذا مُرّرت قيمة فارغة صراحة إلى دالة البيانات الوصفية، فإنها تحذف الحقول المطلقة بدل اختراع نطاق. المتغيرات التي تبدأ بـ`VITE_` علنية وتُدمج في الملفات المنشورة؛ لا تضع أسرارًا فيها.

النسخة الأساسية في Coolify والنسخة الإضافية في GitHub Pages بيئتا نشر منفصلتان. يضبط workflow الخاص بـGitHub Pages المتغير `VITE_NOINDEX=true` لمنع فهرسة النسخة الإضافية، مع توجيه روابط `canonical` إلى `https://abdulsalam.pro/`. يبقى `BASE_URL` مسؤولًا عن مسار ملفات النسخة المحلية وروابطها، لذلك لا يضيف البناء تحت `/abdulsalam/` هذا الجزء إلى الروابط الأساسية على نطاق الإنتاج. لا تضبط `VITE_NOINDEX=true` على النسخة الأساسية إذا أردت فهرستها.

أعد البناء والنشر بعد تعديل هذه المتغيرات. تعديلها في الخادم بعد إنشاء `dist` لا يغيّر الملفات الثابتة الموجودة بالفعل. نجاح GitHub Pages لا يؤكد تحديث نسخة Coolify؛ تحقق من نشر كل بيئة على حدة.

```powershell
npm run build
npm run check:seo
```

ينفّذ `npm run build` سكريبت `scripts/build.mjs` لإنشاء صفحات HTML ثابتة مستقلة إلى جانب الملفات التفاعلية. يفحص `npm run check:seo` مخرجات البناء محليًا. يظل التحقق من HTTP وCDN والفهرسة الفعلية مطلوبًا بعد النشر. هذه التعديلات محلية؛ لم يُنفّذ نشر الإنتاج ضمن هذه المراجعة.

## المحتوى والبيانات

- `src/data/profile.ts`: الهوية وبيانات الاتصال والأسئلة الشائعة، وهي مشتركة بين المحتوى الظاهر والبيانات المنظّمة.
- `src/data/projects.ts` وملفات دراسات المشاريع: الوصف والتقنيات والأدوار. أضف أدلة وروابط أصلية حين تكون متاحة للنشر، دون كشف أعمال خاصة أو نسب نتائج غير مقاسة.
- `src/lib/seo.ts`: عنوان ووصف مستقلان لكل صفحة، وروابط أساسية، ووسوم المشاركة، وبيانات JSON-LD عن الشخص والموقع والصفحة ودراسة المشروع ومسار التصفح.

الأسئلة الشائعة تظهر للزائر في صفحة «عني»، وتستخدم النص نفسه في JSON-LD. وجود `FAQPage` لا يَعِد بمظهر خاص في Google. لا تُضَف تقييمات أو أسعار أو تواريخ أو نسب نجاح غير مثبتة إلى البيانات المنظّمة. عند تعديل النص الظاهر، راجع توافقه مع عنوان الصفحة ووصفها وبياناتها.

## فحص نسخة الإنتاج

### نتيجة المراجعة في 28 أكتوبر 2026

فُحص النطاق الأساسي عبر HTTP قبل النشر: الصفحة الرئيسية أعادت `200` وبداخلها `root` فارغ، وملفا `robots.txt` و`sitemap.xml` أعادا `404`. أعاد رابط تجريبي غير موجود `404` أيضًا، وهي استجابة صحيحة يجب الحفاظ عليها.

البناء المحلي الجديد ينتج 19 صفحة مستقلة (الرئيسية و6 أقسام و12 مشروعًا)، وصفحة `404.html` غير قابلة للفهرسة، وخريطة بـ19 رابطًا رسميًا، وملف `robots.txt`، ودليل اختياري `llms.txt`. نجحت فحوص العناوين والوصف والروابط والبيانات المنظّمة وتوافق الأسئلة الشائعة مع المحتوى الظاهر ووجود الأصول. نجح كذلك بناء المسار `/abdulsalam/` وفحص نسخة `noindex` الخاصة بالمرآة.

تأكدت المعاينة في المتصفح من التنقل إلى المشاريع وتحديث canonical والوصف، وفتح مشروع مباشرة دون أخطاء hydration، وظهور المحتوى على عرض جوال 390px دون تجاوز أفقي. تمت معاينة صفحة «عني» دون تحميل سكريبت التطبيق للتأكد من بقاء المحتوى ظاهرًا. هذه فحوص محلية، ولا تعني اكتمال الفهرسة أو اجتياز Core Web Vitals ميدانيًا.

### بعد رفع مجلد dist

1. افتح الصفحة الرئيسية وصفحة «عني» وقائمة المشاريع وصفحة مشروع مباشرة، ثم أعد تحميل كل رابط. يجب أن تحصل على الصفحة الصحيحة دون الحاجة إلى زيارة الرئيسية أولًا.
2. عطّل JavaScript أو استخدم «عرض مصدر الصفحة». يجب أن يحتوي HTML على المحتوى الأساسي والروابط، وليس عنصر `root` فارغًا فقط.
3. راجع أن كل صفحة لها عنوان ووصف و`canonical` خاص بها، وأن JSON-LD صالح. استخدم [اختبار النتائج المنسّقة](https://search.google.com/test/rich-results) و[Schema Markup Validator](https://validator.schema.org/). ليست كل أنواع Schema.org مؤهلة لنتائج منسّقة في Google.
4. افتح `robots.txt` و`sitemap.xml` على النطاق الأساسي، وتحقق من أن عناوين الخريطة تنتمي إليه وتعيد استجابة `200`، وأن خريطة الموقع لا تحتوي روابط `#` أو صفحات تجريبية أو صفحات خطأ.
5. اختبر رابطًا غير موجود. يجب أن تعيده الاستضافة بحالة HTTP `404`، وألا تحوّل جميع المسارات غير المعروفة إلى الرئيسية بحالة `200`؛ قد ينتج عن ذلك أخطاء soft 404. إعداد حالة HTTP مسؤولية الاستضافة حتى مع وجود صفحة خطأ ضمن الملفات الثابتة.
6. افحص النطاق من خارج الشبكة المحلية، وتأكد من أن الجدار الناري وCDN لا يطلبان CAPTCHA من زواحف البحث الموثقة. سماح `robots.txt` وحده لا يتجاوز حجب الخادم.
7. شغّل PageSpeed Insights على الجوال، وراجع LCP وINP وCLS بعد النشر. استخدم القياسات الفعلية لتحديد الأولوية، خاصة للفيديو والصور والخطوط؛ نجاح البناء لا يثبت أداء Core Web Vitals في الاستخدام الفعلي.

## تفعيل أدوات البحث

أضف النطاق الأساسي إلى [Google Search Console](https://search.google.com/search-console/) وأثبت ملكيته بالطريقة المناسبة، ثم أرسل رابط `sitemap.xml`. استخدم «فحص عنوان URL» للتأكد من الوصول والمحتوى والرابط الأساسي الذي اختاره Google، واطلب فهرسة الصفحات المهمة عند الحاجة. يمكن إضافة الموقع كذلك إلى [Bing Webmaster Tools](https://www.bing.com/webmasters/).

راقب تقارير الفهرسة وعمليات البحث والنقرات عبر عدة أسابيع. إرسال الخريطة أو طلب الفهرسة لا يضمنان الإدراج الفوري. حدّث دراسات المشاريع بأمثلة واقعية وروابط إلى الحزم أو المستودعات المسموح بنشرها، وحافظ على تطابق الاسم وروابط GitHub وLinkedIn مع الهوية العامة.

## GEO: الظهور في البحث وإجابات الذكاء الاصطناعي

توضح [إرشادات Google لميزات الذكاء الاصطناعي](https://developers.google.com/search/docs/appearance/ai-features) أن أساسيات SEO تظل مطلوبة، ولا توجد ملفات أو مخططات إضافية خاصة تضمن الظهور. يفيد المحتوى النصي الواضح، والروابط القابلة للزحف، وتحديد صاحب المحتوى، وشرح الدور والتقنيات في كل دراسة مشروع.

للظهور في بحث ChatGPT، راجع [إرشادات زواحف OpenAI](https://developers.openai.com/api/docs/bots): يسمح `OAI-SearchBot` بالوصول لأغراض البحث، بينما تتحكم إعدادات `GPTBot` في غرض مختلف متعلق بالتدريب. لا يتطلب تحسين ظهور الموقع في البحث فتح التدريب. راجع إعدادات CDN وحماية البوتات أيضًا.

ملف `llms.txt` ليس شرطًا في Google أو ضمانًا للاستشهاد بالموقع. الأولوية لإتاحة الصفحات الفعلية والمحتوى الأصلي والأدلة ومراجعة الأداء والفهرسة بعد النشر.

المراجع التقنية: [أساسيات JavaScript وSEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)، [الروابط الأساسية](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)، [بيانات صفحات الملف الشخصي](https://developers.google.com/search/docs/appearance/structured-data/profile-page).
